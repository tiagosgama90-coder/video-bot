# AGENTS.md

## Cursor Cloud specific instructions

### What this project is
`sidusastro-video-bot` is a [Remotion](https://www.remotion.dev/) project that generates
vertical (1080x1920) astrology/horoscope videos and publishes them to social media.
It is a set of Node/TypeScript scripts plus a Remotion composition — there is no
long-running server other than the Remotion Studio dev preview.

- Video composition: `src/Root.tsx` + `src/MyVideo.tsx` (composition id `HoroscopoComposition`).
- Generation/publish scripts (root `.ts` files, e.g. `gerar-e-publicar.ts`) use Azure Speech
  (TTS narration), Firebase Storage (asset hosting) and the Buffer API (TikTok/Instagram publishing).
- CI/scheduling lives in `.github/workflows/*` (triggered via `workflow_dispatch` / cron-job.org).

### Standard commands (see `package.json` scripts)
- Dev app / preview: `npm run dev` (runs `remotion studio` on http://localhost:3000).
- Lint + typecheck: `npm run lint` (runs `eslint src && tsc`). Passes with only warnings.
- PR CI check: `npm run verificar-deploy` (this is what `.github/workflows/validar-scripts.yml` runs on PRs).
- Render a video: `npx remotion render HoroscopoComposition out/<name>.mp4 [--props=<file>]`.

### Non-obvious caveats
- Rendering (not the studio preview) needs system tooling that is NOT installed by `npm`:
  `ffmpeg` (apt) + Remotion's Chrome Headless Shell (`npx remotion browser ensure`, downloaded
  into `node_modules/.remotion/`). These are provided by the VM snapshot. `npm ci` wipes
  `node_modules`, so the startup update script re-runs `npx remotion browser ensure` to restore Chrome.
  If a render fails with a missing-browser error, run `npx remotion browser ensure` manually.
- The default background image in `src/Root.tsx` is a remote Wikimedia URL that returns 403 to
  headless Chrome, so a plain `npx remotion render HoroscopoComposition` fails on image load.
  To render locally, pass `--props` with `imagemFundoUrl` set to a local file in `public/`.
- The composition references audio via `staticFile('narracao.mp3')` and a `musica-*.mp3` file.
  These (and background images) are generated by the pipeline at runtime and are gitignored
  (see `.gitignore`). For a local test render, create placeholder assets in `public/`
  (e.g. with `ffmpeg -f lavfi -i "sine=..." public/narracao.mp3`). The studio preview still loads
  without them (audio just 404s).
- Generation/publish scripts (`npm run gerar`, `gerar-segunda`, etc.) require external secrets
  (`BUFFER_ACCESS_TOKEN`, `AZURE_SPEECH_KEY`, `FIREBASE_STORAGE_BUCKET`, `firebase-admin.json`,
  Buffer channel IDs). See `.env.example` and the `env:` blocks in `.github/workflows/*.yml`.
  Without these secrets you can still run lint, the CI check, the studio, and local renders.
